Reconciled against `docs/BUILD_ARENA_PLAN.md`, `MY_plan.md`, and last commit

## Locked decisions

- DSL grammar is `block_objectId@x,y,z+(axisCount)` or `block_objectId@x,y,z-(axisCount)`.
  Example: `oak_planks_1@0,1,0-(x5)`.
- Count is **total blocks including the origin**. `-(x5)` places five cubes, not origin plus five extra.
- Keep the last-commit **two sliders**. Do not collapse X/Y/Z into one size.
  - Platform width (X and Z together): odd integers. Core allows `3…101`. UI slider min is `7`.
  - Build height (max Y): core allows `1…31`. UI slider min is `7`.
  - Live editor boots at **51 × 51 platform, maxY 31** (`createArenaConfig(51, 31)`).
  - Test helper `DEFAULT_ARENA_CONFIG` stays 7×7, maxY 6.
- Resize stays human-only. WebMCP must **not** expose `resize_arena`, `resize_platform`, or `resize_height`. Agents may **read** current bounds via `get_arena_context`.
- Shrink that would drop any block still fails atomically and never auto-deletes.
- Match last-commit history: grow keeps placement undos; shrink **clears** undo history; resize itself returns `undoId: null` (the size change is not an undo step).
- Unchanged size is a no-op (no revision bump).
- `set_blocks` stays capped at **256**. Do not invent a 3150 cell cap.
- Renderer paginates engine reads and grows instance capacity as needed up to current bounds (max platform 101, maxY 31).
- Shape / transform commands may fill the **current** `ArenaConfig` and must support `dryRun`.
- Phase 6 export uses **schemaVersion 2** (object ids and block state). schemaVersion 1 full-cube files still import via an explicit migration documented in code.

`MY_plan.md` and `docs/BUILD_ARENA_PLAN.md` still show the older short DSL (`oak_planks_1-(x5)`), unified-or-deferred resize wording, and schemaVersion 1 samples. This file wins for Phases 4–6 until those docs are updated.

## Phase 5 — WebMCP

The current official draft uses `document.modelContext.registerTool(tool, { signal })`; aborting the signal removes page-scoped registrations. Tools should register once and read fresh engine state during execution. [Official WebMCP specification](https://webmachinelearning.github.io/webmcp/), [spec source](https://github.com/webmachinelearning/webmcp/blob/main/index.bs).

### Task 1: Serial WebMCP contract freeze — Codex

Create and commit the shared contract before creating parallel worktrees.

**Starter tools**

- Reads: `get_arena_context`, `get_build_summary`, `query_blocks`, `get_build_slices`
- Writes: `set_blocks`, `undo_build_change`, `save_blueprint`
- Deferred: `generate_shape`, `transform_region`, `render_build_views`, DSL
- Never: any resize tool. Size is human-slider only. Reads already return bounds and revision.

**Contract rules**

- Exact `snake_case` names.
- `additionalProperties: false`.
- Writes require `expectedRevision`.
- Reads return observed revision.
- Writes return revision, affected blocks/bounds, warnings and `undoId`.
- `save_blueprint` returns canonical `BlueprintV1`; human download remains a UI action.
- Thin handlers call `ArenaEngine`; no Three.js/Zustand mutation.
- Feature-detect `document.modelContext`; normal UI works without it.

### Task 2: Create three worktrees

- `p5/schemas`
- `p5/handlers`
- `p5/tests`

All branch from the WebMCP contract commit.

## Phase 6 — Advanced operations, partial blocks and DSL

Human resize already exists. Phase 6 does **not** invent a third resize model.
Freeze the last-commit resize contract, then add shapes, transforms, partials,
object groups, DSL, and blueprint v2.

### Task 1: Serial core foundation — Codex

Freeze and implement the shared Phase 6 contracts before parallel branches.

**Arena size (already in last commit — freeze, do not rewrite)**

- Two independent human controls, already wired:
  - `resizePlatform(platformSize)` — odd X/Z width, centred on 0.
  - `resizeHeight(buildHeight)` — max Y.
- Core limits: platform `3, 5, …, 101`; height `1…31`.
- UI sliders: platform min 7 / max 101; height min 7 / max 31.
- Editor start: 51 × 51, maxY 31. Platform stays implicit at `y = 0`.
- Shrink rejects if any block would fall outside; never auto-delete.
- Grow: revisioned; placement undo history kept; size change itself is not undoable.
- Shrink: revisioned; undo history cleared; size change itself is not undoable.
- No-op when unchanged.
- WebMCP must not call these methods.

**Advanced commands (new)**

- `generate_shape`: floor, wall, filled box, hollow box. Roofs stay later.
- `transform_region`: copy, move, rotate, mirror, replace type.
- History records block and object-group changes atomically. Config/size history stays as in the last commit (not a user-undoable resize step).

**Partial block contract**

- IDs: `water`, `lava`, `oak_slab`, `oak_stairs`, `oak_fence`, `stone_wall`, `oak_trapdoor`
- Slab: top/bottom.
- Stairs: facing, top/bottom, initially straight.
- Trapdoor: facing, top/bottom, open.
- Fence/wall connections derive from neighbours.
- Water/lava are static visuals.

**Persistent object grouping**

- Blocks may carry `objectId`.
- DSL/shape group IDs persist into blueprint JSON and Layers.
- Reusing an existing group appends only when its block type is compatible.
- Transforms and undo/redo preserve grouping.

**Blueprint v2**

- Export `schemaVersion: 2` with object ids and block state.
- Import still accepts schemaVersion 1 full-cube files; migrate in one documented function.
- Never leave a half-migrated world.

Commit this foundation, then branch the three Phase 6 worktrees (`p6/dsl`, `p6/renderer`, `p6/webmcp`).

### Task 3A: DSL engineer — parallel
